# dsh-vim-control

Modal, keyboard-driven navigation of the DeepSeek Harness Web GUI. This is not
modal *text editing*: the composer keeps its own editor and history, and this
plugin never touches a draft. What it moves is the shell itself — the row cursor,
the session selection, and the subagent catalog.

## Keys

| Chord | Action |
|---|---|
| `j` / `k` | Next / previous row; the conversation scrolls with the cursor |
| `gg` / `G` | First / last row |
| `Ctrl+d` / `Ctrl+u` | Page the conversation down / up, cursor settling on the centre |
| `Enter` | Open the row under the cursor |
| `]c` / `[c` | Next / previous conversation |
| `]a` / `[a` | Next / previous subagent |
| `g s` | Toggle the session sidebar |
| `g a` | Open the subagent list |
| `g c` | Back to the conversation |
| `:` | Command line |
| `?` | Key list |
| `i` / `Esc` | Focus the composer and enter insert mode / return to normal mode |

NORMAL mode owns only unmodified keys plus `Ctrl+d`/`Ctrl+u`. Focusing any text
surface (composer, rename field, search) switches to INSERT and passes every key
through. `Esc` returns to NORMAL from anywhere, including the composer: it blurs
the editor, and only an open menu, listbox, or dialog keeps Escape for itself. `i`
focuses the composer and returns to INSERT. Switching conversations stays in
NORMAL and lands in the conversation: the shell puts focus in the new composer
while opening it, and the plugin drops that focus instead of treating it as
typing, so `j`/`k` carry on scrolling the new conversation. `Ctrl+d`/`Ctrl+u`
page the scroll container itself and snap the cursor to the row nearest the
viewport's centre. While a Host dialog is open, the plugin stays out of the way
entirely.

## Commands

| Command | Effect |
|---|---|
| `:o <session-id>` | Open that session |
| `:new` | Start a session in the current workspace |
| `:s` | Toggle the session sidebar |
| `:a` | Open the subagent list |
| `:c` | Back to the conversation panel |
| `:help` | Key list |
| `:q` / `:vim off` | Turn vim control off |

The master switch is the `VIM` chip at the bottom-right of the frame; its state
is stored per origin, and clicking it turns the plugin on or off.

## How it works

- **Conversations** are sessions. Session rows in the sidebar carry
  `data-row-key="session:<id>"`, `aria-selected`, and their own click handler, so
  `]c` / `[c` reads the rendered order (grouped, pinned, filtered) and opens the
  neighbour through the public `uiWorkspace.openSession()`.
- **Rows** carry `data-chat-flow-key`; the cursor is an inset ring plus
  `scrollIntoView`, so the shell's own scrolling and paging stay authoritative.
- **Subagents** are driven through the header catalog popover (`role="tree"`),
  whose rows open their child through the same workspace navigation. The
  trigger carries no data attribute, so it is matched by the `_trigger` suffix of
  its CSS-module class after every other button has been ruled out.
- Everything else is a public Client service: `layout.toggleSidebar()`,
  `layout.selectPanel(null)`, `uiWorkspace.startSession()`.

No shipped row is replaced or disabled; the plugin adds one `shell.overlay`
entry and one capture-phase key listener.

## Known limitations

- **DOM contract, not API.** Row attributes and the subagent trigger are the
  shell's rendered contract; a Harness upgrade may rename them. The TypeScript
  and the pure key table survive such a change, the selectors do not.
- **The subagent trigger is a heuristic.** If a future header stops rendering a
  `_trigger` button, `g a` reports "no subagent list" instead of opening it; the
  key still works once the popover is open by hand.
- **`Ctrl+d` is the browser's bookmark chord.** While NORMAL mode is active and
  no text surface has focus, the plugin consumes it for half-page navigation.
- **No visual mode, registers, or text objects.** The plugin navigates the
  shell; it does not edit a document.

## Install

The package is linked into a profile like every other local plugin:

```sh
# in the profile's package.json dependencies
"dsh-vim-control": "link:../../plugins/dsh-vim-control"
# and in dsh.profile.bundles
"dsh-vim-control"
```

Then `pnpm install` in the profile and restart the harness (a newly linked
module resolves at boot).

## Development

```sh
pnpm install
pnpm build      # tsc (Host) + tsc --noEmit (Client types) + esbuild wrapper
pnpm test       # node --test: manifest shape, loader bundle, key router
```

`lib/client.js` is generated by `scripts/build-client.mjs`: esbuild emits
CommonJS with `react` and friends external, and the script wraps it in the
`window.__ModuleLoader__.load({ id, factory })` envelope the page expects.
